# T07: Hardware auto-detection + configuration

## Description
`device.py`: try MLX (Apple Silicon and `mlx` importable), then CUDA (`torch.cuda.is_available()`), then CPU. Overrides: `MEDEXTRACT_DEVICE=auto|mlx|cuda|cpu` and `MEDEXTRACT_MODEL_ID`. Pick the default model per backend. Import heavy libraries (mlx, torch) lazily.

## Acceptance criteria
- [x] Unit tests simulate all 3 hardware cases
- [x] `medextract info` reports the right backend on this machine (mlx)

## Files
- `src/medextract/device.py`
- `src/medextract/config.py`
- `tests/test_device.py`

## Notes
- Implemented `config.py` (`Settings`, `from_env`) and `device.py` (`mlx_available`, `cuda_available`, `detect_backend`, `resolve_model_id`, `create_backend`, `DEFAULT_MODELS`).
- `tests/test_device.py`: 39 tests. Mac/MLX, NVIDIA and CPU-only cases are simulated by patching `platform`, `find_spec` and a fake `torch` module. Explicit-but-unavailable choices raise `VLMError` with an install hint. Env parsing and invalid values are covered. A subprocess test checks that importing `device`/`config` does not load mlx, torch or transformers.
- `medextract info` on this machine: `selected_backend` = `mlx`, `model_id` = `mlx-community/Qwen3-VL-8B-Instruct-4bit`, `mlx_available` = true, `cuda_available` = false.
- `Settings.from_env(**overrides)` ignores `None` overrides, so unset CLI options do not override the environment.
- `cpu` is always selectable explicitly. Its availability is only checked when the model loads (the transformers backend raises a `VLMError` with the `[cpu]` hint).
