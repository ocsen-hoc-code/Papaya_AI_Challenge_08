# T16: Validation

## Description
Valid dates and discharge >= admission; positive amounts; each line `quantity x unit_price ~= total`; `sum(items.total)` vs `grand_total` (flag if off by more than 5%); lab flags consistent with `reference_range` (recomputed in code).

## Acceptance criteria
- [x] Unit tests for each rule
- [x] Errors go into `validation_errors` in a structured form (field, code, message)

## Files
- `src/medextract/validate.py`
- `tests/test_validate.py`

## Notes
- Implemented in `src/medextract/validate.py`; 65 tests in `tests/test_validate.py` pass (with T05, 181 in both files).
- Severities: `invalid_date`, `invalid_amount`, `non_positive_amount`, `invalid_quantity`, `date_order`, `total_mismatch` and `invalid_value` are errors. `ambiguous_date`, `future_date`, `line_total_mismatch`, `lab_flag_mismatch`, `incomplete_items` and `missing_required` are warnings.
- `total_mismatch` is an error (the spec gives no severity). Its percentage is relative to `grand_total`. The check is skipped when any item has no total and no quantity x unit_price (`incomplete_items` is reported instead), because a partial sum would be wrong.
- `missing_required` treats an empty list as missing as well as None. It is not reported when the field already has an invalid normalization.
- Lab reference ranges: ranges, `<`, `<=`, `>`, `>=` (with en dash or em dash, and trailing units). Two or more numeric ranges (for example male and female) return None rather than a guess.
- Wrong-typed values skip their rule. Nothing raises.
