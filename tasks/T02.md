# T02: Smoke-test MLX + Qwen3-VL-8B-4bit

## Description
Download `mlx-community/Qwen3-VL-8B-Instruct-4bit`, run one image from `document-tests/`, and measure tokens/s, RAM and prefill time. Check whether `mlx-vlm` exposes logprobs and works on Python 3.13. Record the results in this task's Notes.

## Acceptance criteria
- [x] The model produces a text description of one document
- [x] tokens/s, RAM and logprobs availability are recorded

## Files
- `scripts/smoke_mlx.py`

## Notes
Run on 2026-10-22, `scripts/smoke_mlx.py document-tests/01_receipt_en.pdf` (M3 Pro, 18 GB, Python 3.13, mlx-vlm 0.7.10, mlx 0.32.4):
- Works on Python 3.13. Load 2.2 s (weights cached), peak memory 6.93 GB.
- Page image 1131x1600 -> ~1800 prompt tokens, prefill 155 tok/s (~12 s), generation 27.6 tok/s.
- Output was correct JSON (hospital, patient, date as printed). The model labeled the type with the printed title "OFFICIAL RECEIPT", so prompts must enumerate the allowed type values.
- Logprobs: yes. `stream_generate` yields the full log-softmax over the vocabulary per step; the chosen token's logprob is `chunk.logprobs[chunk.token]`. Mean token prob was ~1.000 on clean printed text, so logprobs are only a weak signal and should be used per field (min prob over the value's tokens), not averaged.
- Estimate: ~2 calls per document (classify ~15 s, extract ~30-40 s) -> ~50 s/document, ~8-9 min for the 10 documents sequentially on the GPU.
